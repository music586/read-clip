# 阅读摘抄站点设计

## 1. 目标

建立一套以 Markdown 为内容源的阅读摘抄系统。用户在本地编辑器中记录摘抄，推送到 GitHub 后，系统自动生成并发布到 GitHub Pages，方便按时间、标签和来源浏览，也可全文搜索。

首版以低维护成本和可靠发布为优先，不依赖数据库或常驻服务器，并为未来接入网页表单和浏览器插件保留统一的数据格式。

## 2. 首版范围

首版包含：

- 每条摘抄保存为独立 Markdown 文件。
- 本地编辑、Git 提交与推送的录入流程。
- 首页时间流、全文搜索、标签导航、来源聚合和摘抄详情页。
- 每条摘抄可设为公开或私密。
- 响应式页面、浅色/深色模式和 RSS。
- GitHub Actions 自动校验、构建并部署到 GitHub Pages。

首版不包含登录、在线编辑、点赞、评论、阅读进度、复杂知识图谱和统计仪表盘。网页表单和浏览器插件属于后续阶段。

## 3. 技术方案

采用以下技术组合：

- Astro：生成静态站点并管理内容集合。
- Markdown Content Collections：保存摘抄并校验元数据。
- Pagefind：为构建后的公开页面生成本地全文搜索索引。
- GitHub Actions：执行校验、测试、构建和部署。
- GitHub Pages：托管公开静态站点。

该方案不需要服务端运行环境。公开站点仅包含构建时筛选后的内容，后续录入工具也可继续写入相同的 Markdown 格式。

## 4. 系统架构

内容发布链路如下：

```text
本地 Markdown 摘抄
        ↓
Git 提交并推送 GitHub
        ↓
GitHub Actions
  ├─ 校验内容结构
  ├─ 排除私密内容
  ├─ 生成页面与聚合数据
  ├─ 生成全文搜索索引
  └─ 验证公开构建产物
        ↓
GitHub Pages
```

系统分为五个边界清晰的模块：

1. **内容层**：读取独立 Markdown 文件，通过统一 schema 校验字段。
2. **构建层**：在生成公开内容前过滤私密记录，并计算标签、来源和时间聚合。
3. **页面层**：负责时间流、搜索、标签、来源及详情页面。
4. **搜索层**：Pagefind 对公开静态页面建索引，在浏览器本地查询。
5. **发布层**：GitHub Actions 在主分支更新后部署，失败时保留现有线上版本。

## 5. 内容模型

文件按日期归档，例如：

```text
src/content/clips/2026/08/2026-08-28-reading-as-thinking.md
```

单条内容格式如下：

```markdown
---
title: "阅读也是一种思考"
source: "如何阅读一本书"
author: "莫提默·J·艾德勒"
url: "https://example.com/book"
tags:
  - 阅读
  - 学习方法
createdAt: 2026-08-28T20:30:00+08:00
private: false
---

真正的阅读，是读者与作者共同参与的一种思考活动。
```

字段定义：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | 字符串 | 是 | 摘抄的简短标题 |
| `source` | 字符串 | 是 | 书籍或文章名称 |
| `author` | 字符串 | 否 | 来源作者 |
| `url` | URL 字符串 | 否 | 原文地址 |
| `tags` | 字符串数组 | 否 | 标签，默认空数组 |
| `createdAt` | 含时区的日期时间 | 是 | 记录时间 |
| `private` | 布尔值 | 否 | 是否排除在公开站点外，默认 `false` |
| Markdown 正文 | Markdown | 是 | 摘抄原文，不允许为空 |

页面 slug 根据文件相对于摘抄目录的路径稳定生成。文件移动会改变 slug，因此已发布文件默认不移动；如需整理，使用显式重定向表维护旧链接。

来源聚合键由规范化后的 `source` 与 `author` 共同组成。规范化只清理首尾空白及连续空白，不进行模糊合并，以免错误地把不同来源归为一组。需要合并时统一修改相关文件中的来源字段。

## 6. 隐私边界

`private: true` 表示该记录在页面生成前被过滤，不得进入：

- HTML 页面
- 搜索索引
- 标签和来源计数
- RSS
- 站点地图
- 社交分享元数据

该字段不能保护公开 GitHub 仓库中的原始文件，因此采用明确的双仓库边界：内容与站点源码保存在私有仓库，GitHub Actions 完成过滤和构建后，仅将静态产物发布到独立的公开 Pages 仓库。公开仓库不保留 Markdown 原文、源码或构建历史中的私密内容。发布凭据只授予目标仓库写入权限，并保存在私有仓库的 Actions secrets 中。

构建完成后执行敏感内容扫描：收集所有私密记录的唯一标题和正文指纹，确认其未出现在公开产物中。该检查是过滤逻辑之外的第二道防线。

## 7. 页面与功能

### 7.1 首页与时间流

- 按 `createdAt` 倒序展示公开摘抄。
- 卡片展示正文摘要、来源、作者、标签和日期。
- 长内容显示摘要并链接到详情页。
- 使用静态分页，控制初始页面体积。

### 7.2 全文搜索

- 搜索公开摘抄的正文、标题、来源、作者和标签。
- 输入后即时显示结果并高亮关键词。
- 支持中文搜索。
- 无结果时提供清除查询和筛选的操作。
- 搜索完全在浏览器本地执行，不将查询发送给第三方。

### 7.3 标签

- 展示全部公开标签及对应摘抄数量。
- 每个标签拥有可收藏、可分享的独立 URL。
- 标签页按时间倒序展示摘抄。
- 可在标签结果中继续全文搜索。

### 7.4 来源

- 以书架或列表形式展示来源、作者、公开摘抄数和最近记录时间。
- 每个来源拥有独立详情页。
- 来源详情页集中展示该来源下的全部公开摘抄。

### 7.5 摘抄详情

- 展示完整正文、来源、作者、标签和记录时间。
- 存在 `url` 时显示“查看原文”。
- 提供复制摘抄正文和复制当前页面链接的操作。
- 展示同一来源下的其他公开摘抄。

### 7.6 全局体验

- 主导航包含首页、搜索、标签和来源。
- 浅色与深色模式默认跟随系统，并允许手动切换。
- 手机端使用单栏布局，桌面端限制正文宽度以保证可读性。
- 为详情、标签和来源页生成合适的标题、描述和分享元数据。
- RSS 按记录时间发布公开摘抄。

## 8. 内容录入与发布流程

1. 用户从仓库内的摘抄模板创建文件。
2. 用户填写元数据与正文，并运行本地预览或内容校验。
3. 用户提交并推送到主分支。
4. GitHub Actions 依次执行内容校验、自动化测试、站点构建、搜索索引生成和隐私产物检查。
5. 全部步骤成功后部署；任何步骤失败都不替换现有线上版本。

## 9. 错误处理

- 必填字段或正文缺失时，构建失败并显示具体文件及字段。
- 日期、URL 或字段类型无效时，输出可操作的错误提示。
- 生成的 slug 重复时阻止构建，避免页面覆盖。
- 外部原文链接失效不阻止构建，因为第三方可用性不应影响站点发布。
- 部署失败时保留上一版本，并在 GitHub Actions 中记录失败阶段。
- 搜索脚本加载失败时，其余静态页面仍可正常浏览。

## 10. 测试与验收

自动化验证覆盖：

- 内容 schema 接受合法样例并拒绝各类非法样例。
- 私密记录不进入任何公开页面、索引、聚合、RSS 或站点地图。
- 时间排序、静态分页、标签计数和来源归组正确。
- 搜索覆盖中文正文、标题、作者、来源和标签。
- 主要页面在手机与桌面视口下可用。
- GitHub Pages 使用项目子路径时，资源、导航和站内链接正确。
- 构建产物的隐私扫描能够发现模拟泄漏并使流水线失败。

首版通过以下场景验收：

1. 新增一条公开摘抄并推送后，它自动出现在时间流、搜索结果、对应标签、来源页、详情页和 RSS 中。
2. 新增一条 `private: true` 的摘抄并推送后，公开构建产物中不存在其正文、标题或相关聚合信息。
3. 提交格式错误的摘抄时，部署被阻止，并明确指出需要修改的位置。
4. 整套公开站点无需数据库或常驻服务器即可运行。

## 11. 后续演进

在首版的数据格式和构建边界稳定后，按以下顺序演进：

1. 网页录入表单：通过受控身份认证向内容仓库创建 Markdown 文件或 Pull Request。
2. 浏览器插件：选中文字后填充来源信息，并复用网页录入接口。
3. 可选的个人批注、章节页码、阅读进度和关联摘抄字段。

后续入口必须复用本设计的内容 schema，不直接依赖站点页面内部实现。
